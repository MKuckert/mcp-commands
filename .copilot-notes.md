# Copilot review notes on PR #38 (feature/logging-revised)

10 comments. For each: location, quoted claim.

## 1. server.go:288 (stdinIdentityTee.inspect)
> This append is unbounded until a newline arrives. A malformed or very large stdio frame can therefore grow `partial` indefinitely and exhaust process memory before the SDK handles it. Cap identity inspection per line and enter a discard-until-newline state while continuing to pass all bytes through unchanged.

## 2. execute.go:284 (failure records)
> The failure records diverge from the PR contract in both directions: `outputAttrs` is attached to WARN, exposing up to 2 MiB of raw tool output at the default `info` level, while the TRACE record is rebuilt before the timeout attribute is added and therefore omits the effective timeout. Resolve the documented contract consistently; if output is TRACE-only as the PR description states, WARN should use only the failure metadata and TRACE should add output to that complete metadata set.

## 3. http.go:489 (clientInfoFromBody)
> The fallback splits the body before trying to parse it as one message, so a valid pretty-printed multi-line `initialize` request is never recognized. Parse the complete body as a single message first, then fall back to line-by-line NDJSON parsing.

## 4. server.go:135 (shutting down)
> This logs `reason=signal` for internal cancellation too. For example, the watch-error path calls `cancel()` and waits for `Shutdown`, guaranteeing this message even though no signal occurred; bind failures can also trigger it via deferred cancellation. Wait on a signal-only context or carry the actual shutdown reason separately.

## 5. server.go:218 (stdio signal path)
> The stdio signal path never emits the documented `shutting down` lifecycle record; only HTTP has that log site. Emit it in this branch before waiting for `serveDone`.

## 6. watch_test.go:1032 (TestWatchPerEventLogs)
> `watchChanges` writes to `logBuf` on its goroutine while this loop calls `String()` (and later `Reset()`) concurrently. `bytes.Buffer` is not concurrency-safe, so this test has a data race and can observe corrupted output. Use the package's locked capture writer and avoid resetting it, or add synchronization around all accesses.

## 7. README.md:307 (sample record)
> The section calls this a TRACE record, but the sample starts with `WARN`. Use the actual TRACE prefix (or rename the example) so readers can identify the new level correctly.

## 8. http.go:458 (HTTP identity record)
> The PR description requires client identity records to include the transport, but the HTTP record omits it. Add a stable `transport=http` field so HTTP and stdio identities are distinguishable.

## 9. plans/2026-10-09-logging-revised.md:9 (plan doc)
> This states that `slog.LevelTrace` exists in the standard library, but the implementation correctly defines its own `levelTrace = slog.Level(-8)` because no such constant exists. Update the plan so its locked design matches the code.

## 10. server.go:298 (stdio identity record)
> The stdio identity record also omits the `transport` field promised by the PR description. Add `transport=stdio` to keep the two transport-boundary records distinguishable.
